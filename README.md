# 随手记 · 一起玩点小游戏，顺手聊聊生活

一个可以自行部署的小游戏与弹幕社区。游戏大厅 `/games` 提供同频猜词，社区广场 `/plaza` 分为游戏交流、游戏资讯、生活日常；弹幕首页继续作为公开内容的动态入口。每条弹幕都是帖子的入口，支持文字、图片、视频、评论、点赞、签到和每日话题。提供八种视觉主题、可选自动变化，以及帖子、评论和每日话题管理端。

弹幕保留全屏布局，电脑最多7行、手机最多6行；实际行数随屏幕可用高度和帖子数量调整，每条弹幕都指向真实帖子。

弹幕在新浏览会话首次进入时随机打散完整内容队列，每个访客独立产生顺序，随后连续循环。相同内容刷新和页面尺寸变化不会再次洗牌，当前标签页重载时恢复已保存的随机顺序与播放进度。打开/关闭帖子、手机浏览器高度变化和相同内容刷新只重排轨道，不从头重建弹幕；当前标签页可使用时，浏览器会临时记录公开帖子编号和播放位置，刷新后尝试接续。内容集合发生变化或浏览器不支持临时存储时正常播放，不依赖存储才能循环。

前端原生 HTML / CSS / JavaScript，后端 Node.js 内置 SQLite，无 npm 运行依赖。源码包含前后端；**GitHub Pages 不能运行本项目后端**。

## 普通用户注册与账号管理

首页顶部“登录 / 注册”提供用户名和密码注册。用户名为3至20位字母、数字或下划线（不区分大小写），新密码为6至12位（已有较长密码仍可登录）；不需要邮箱、短信或额外发信服务。注册前会说明内容归属和必要的账号记录。

未登录可以看弹幕、帖子、图片和评论，发布、评论、点赞和签到需要登录。新发布的帖子和评论在服务器关联固定账号 ID，忽略客户端自行填写的昵称。用户可以在账号窗口退出登录或修改密码；修改密码会注销其他会话。不绑定邮箱，因此没有邮箱找回功能，请保存好密码。

帖子点赞按账号记录：同一账号对同一帖子最多一个赞，数据库唯一约束与计数在同一事务内写入，多设备、连续点击、弱网重试都不会重复计赞。点赞后按钮显示“已赞”；仅帖子作者在首页卡片与详情页看到“查看点赞”。名单接口按帖子关联的作者账号校验，其他登录用户和游客只能看到数量与自己的点赞状态，不能查询名单。站主通过管理端的帖子管理或帖子详情查看名单，使用独立的管理登录会话，后台可查看下架帖及历史匿名帖。名单分页显示账号名并链接至个人空间，空间内容仍遵守原有访问权限；不按帖子显示名称推断作者。退出登录、切换账号或关闭名单会清理名单内容，延迟响应不能恢复已清理数据。点赞名单不包含私密头像、IP、密码或其他个人资料。原来的点赞只记录总数，升级时保存在 `post_heart_history`，不伪造点赞人；名单会标注没有账号记录的历史数量。新记录保存在 `post_hearts`。封禁会阻止继续点赞，已发生的点赞记录保留；下架帖的前台名单与点赞入口不可用，后台可继续核查已有点赞。没有新增私信或自动通知。

站主管理端新增“账号管理”：搜索账号、查看关联帖子及评论、查看注册 IP 和近30天登录记录、封禁或解除封禁。封禁会立即注销全部会话，并阻止该账号登录和发布；已有内容可另行移入回收站。旧匿名帖子不会追认给新账号。

账号和 IP 记录不能证明真实身份，也不能阻止用户用另一个账号重新注册。密码使用加盐 scrypt 派生后保存；会话保存在 HttpOnly Cookie，公网必须 HTTPS。用户隐私记录只向已登录的站主管理端提供，公开帖子接口不会返回这些记录。登录事件只保留近30天，注册 IP 随账号记录保存。

## 个人空间与专属弹幕

登录后从账号窗口进入 `/space`；分享地址为 `/u/用户名`。未自行设置的空间默认仅互关可见，主人可以改为仅粉丝或公开。空间动态、弹幕留言及成员列表都在服务器验证访问权限；已有公开帖子仍保留公开状态。

空间弹幕墙会播放最近30条主人动态和30条好友留言，可以筛选、暂停、展开观看，点击弹幕查看全文。桌面悬停或展开某条弹幕时，其余弹幕继续播放；系统开启减少动态效果时改为静态列表。

有访问权限的登录用户可留下最多80字的弹幕，每10秒最多发送一条。留言关联真实账号，不接受自行填写作者；作者可以撤回，空间主人可以移除。站主管理端可以审核、下架和恢复留言。留言保存在独立的 `space_danmaku` 表，不进入公开弹幕墙或讨论广场。页面显示期间每30秒刷新一次，重新检查权限，取消互关后下一次请求立即拒绝访问。

空间入口会按当前关系显示登录、关注和等待回关的进度。注册后仍需本人确认关注；对方已关注你时使用服务器校验的回关操作。等待回关时，页面可见且已登录才每30秒检查一次，也可手动检查；获得权限后打开空间。网络失败保留门禁，退出账号或新请求开始后，旧响应不会重新显示私人内容。

## 社交消息与邀请

登录后顶部“消息”展示最近90天、最多100条关注、空间留言、帖子评论与回复。消息仅对收件人可见；取消的关注、下架内容及封禁账号的活动不再展示。支持逐条和当前列表全部标为已读。页面可见时每45秒刷新，消息在站内展示，不会发送邮件或系统推送。个人空间提供符合当前权限的邀请文案和互关步骤引导。增长假设和试验计划见 [社交增长计划](docs/social-growth-plan.md)。

## 空间邀请卡

自己的空间提供“制作邀请卡”，按当前空间封面生成1080×1440 PNG，包含账号、空间名称、进入条件及带 `?from=invite` 的二维码。薄荷、晴空、樱花、奶杏四种配色跟随空间设置；修改空间设置后重新制作即可。图中装饰弹幕是固定玩法文案，不代表用户发言；不放入简介、私人动态、留言、粉丝数或访问数据。

支持长按或下载保存、复制邀请，以及设备支持文件分享时调用系统分享面板。由用户选择发送对象；取消或打开面板不计为成功分享。二维码沿用邀请归因链路，制作和下载不会增加到访或转化统计。卡片在浏览器生成，不上传图片；关闭窗口和退出账号会清理页面预览。已保存或发送的图片不会随设置变化而更新，进入时仍由服务器检查当前权限。

## 对话起点与公开冷启动观察

空讨论列表展示可选提问灵感，包含今日管理话题、日常、游戏和校园；选择后只填标题、分类和输入提示，正文为空，仍需本人填写并确认发布。自己的空间也可选择一个问题填入留弹框，手动发送后朋友可定向回复。已有草稿不覆盖，正在回复时不改成新提问，访客不显示主人提问工具。话题服务失败时仍有三个静态提问选项。

本轮公开观察：接口返回12条帖子，作者均为taid1；广场0条讨论，1条可见评论来自帖子作者。观察不涉及注册账号、私人动态或完整留存，不能据此判断全站用户情况。当前增长分析优先小圈子内真实发言和回应，详见 [社交增长计划](docs/social-growth-plan.md)，其中预测情景都是待验证假设。

## 登录后接续编辑

未登录时点击写弹幕、发起讨论或回复评论，登录/注册完成后会回到对应编辑入口并保留目标；只恢复界面，不自动提交任何内容。登录过期导致公开帖、讨论或评论发送被拒绝时，当前标签页的文字和已选附件仍保留，重新登录后可继续编辑并手动确认发布。评论回复恢复前重新读取可见评论，原评论不可见时清除回复关联、保留文字；已离开原帖子则不再跳回旧回复。

关闭登录窗口会取消待接续操作，即便认证请求稍后才成功，也不会重开旧编辑框。主动退出账号会清除当前页的公开帖/讨论/评论草稿和所选附件；草稿不写入服务器或浏览器持久存储，刷新/关闭页面仍可能丢失。账号窗口打开时验证会话，防止过期状态仍停留在已登录界面；旧账号状态请求迟到时不能覆盖新账号或新会话凭据。

本地浏览器验证覆盖过期草稿与附件、回复关联、取消与错误密码、注册接续、原评论不可见、离开帖子和迟到账号状态。后端与迁移45项测试保持通过；发布流程补充账号和广场脚本的语法检查。

## 找朋友与起步提示

朋友动态页提供精确用户名查找，也能粘贴本站 `/u/用户名` 空间链接；输入 `@用户名` 和大小写形式均可。查找只展示公开的空间名称、用户名和可见范围，不展示简介或私人内容。不对站外地址发起请求。搜索结果可主动关注或回关，沿用已有登录、CSRF与回关条件检查。

“这些人关注了你”只向本人展示当前尚未互关的粉丝，按每页6人分页，包含90天前的当前关注；取消关注和封禁后会消失。当前互关、关注和粉丝数来自服务器，起步提示依据曾发布空间动态、当前存在互关朋友和曾给别人留弹/回复的记录生成。提示不会限制浏览，用户可以收起，并按账号在当前浏览器恢复；它不是新的增长统计或强制任务。退出账号会清除列表和查询结果。

展开空间弹幕时会跟随 `visualViewport` 的高度与偏移调整，并在输入时确保表单滚到可见处。浏览器模拟可视区高度400/280/844像素及偏移30像素的检查已通过；这不代替真实Android/iOS软键盘测试。

## 快速回关与空间留言回复

消息中的新关注可以直接“回关”，操作仍需本人点击；服务器重新确认对方仍关注你，已取消的关注返回409而不会创建新关系。已互关的提醒展示当前关系和朋友动态入口，不执行批量或自动回关。

空间弹幕详情支持定向回复。`reply_to_id`关联同一空间中的可见留言，`thread_id`关联原留言；普通旧留言迁移后两字段均为空，正文和下架状态不变。回复仍是空间弹幕，并向原作者提供站内提醒。提醒正文仅在收件人当前仍能访问该空间时返回；点击提醒重新读取具体留言，可定位到不在最近弹幕列表里的原文。原留言下架或原作者封禁后，整条回复链在前台隐藏。中间回复下架时，仍可见的后续回复不再展示被下架的引用正文。

主人可移除，作者可撤回；原留言按钮注明包含其下回复。后台标明随原留言隐藏的回复。定向回复与普通留言共用80字限制、10秒发送间隔、登录/来源/CSRF校验；取消权限、退出账号会清除已显示的私密详情。后台双向留弹指标也按回复的实际被回复者归属计数，不把原空间的主人误当作所有回复的对象。

## 邀请效果统计

从个人空间复制邀请时，链接带有 `?from=invite`。未登录访客进入后以随机 HttpOnly Cookie 近似区分浏览器，首次邀请来源保留7天；已登录访问与识别到的爬虫不计。成功注册、与邀请人完成互关、互关后向邀请人首次留弹分别由服务器记录，客户端不能直接上报转化。站主管理后台“邀请带来的互动”展示近30天访问批次的汇总与阶段转化，最近七天按首次到访日归组，后续动作回填。

重复操作不会重复计里程碑；后续取消关注或撤回留言不回退，封禁受邀账号不计转化。随机浏览器标识只保存哈希，不在该表保存IP或私人正文，记录在新邀请访问时清理90天前数据。不同设备和清除Cookie会造成重复，不能把浏览器数当真人数或把阶段转化当作因果提升。已有注册不追溯补归因；后台可按普通邀请、小红书、QQ、微信、校园小圈子及其他来源，对照普通/A/B文案标签，提供推广邀请生成器。来源标签来自链接并保留首次归因，不证明访问确实来自该平台，也未自动随机分流。未标记的历史记录仍归普通邀请，无法追溯真实渠道。7日回访仅针对统计启用后成熟的受邀激活批次。

邀请来源还区分载体标记：新复制的普通邀请链接携带 `format=link`，新卡片二维码携带 `format=card`；在卡片面板复制文字邀请也记为链接。老链接或未知标记保留 `unknown`，不回填猜测历史来源。载体与渠道/文案一起固定在首次邀请，7天内不因再次打开另一类入口而覆盖。后台“按首次邀请载体标记对照”只给站主展示汇总的到访、注册、互关、首次留弹和到访→留弹比例，原有渠道/文案汇总保持不变。标记可能随复制转发保留，不证明发生了扫码或发送，也不是随机分流试验。

## 朋友动态与关系复访

登录访问 `/friends`，默认聚合互关朋友的空间动态和公开帖子，也可切到“我关注的人”。空间动态在每次请求时检查拥有者是否启用、关注关系和空间权限；不聚合其他人在空间里的留言。弹幕和列表都能点开详情，空间动态可以直接留弹回应，公开帖子可进入原帖评论。取消互关、封禁和下架立即影响后续接口请求；页面每30秒刷新并复核已打开详情。匿名及登出状态清空个人内容，系统减少动态设置会将弹幕改为静态。首页手机底栏也有“朋友”入口。

后台“关系与复访”只对成功发布帖子/空间动态、发表评论和留弹记录按日汇总的账号行为；浏览、刷新、登录、读取消息不计。第7日回访针对统计启用后达成首次留弹的受邀激活用户，按北京时间日历日，第7天完整结束后才进入分母。回访指第7天再次发布上述内容。样本未成熟时展示“待观察”，不输出伪造的留存率。按账号与日保存动作类型及次数，不保存正文或IP；活动记录在写入时每天最多清理一次90天前数据。

近7天双向留弹互关对按当前仍互关、双方近7天都有未下架空间留言或定向回复的无序用户对去重。它不包括所有种类的社交互动，也不能与访问UV等同。匿名公开空间、动态隐私和后台统计的权限保持独立。

## 本仓库共同维护现有阿里云网站

本仓库的 `main` 分支配置了自动部署到现有的 `https://suishouji.online/`：推送后 GitHub Actions 自动测试、上传版本并切换服务，无需站主点击批准。首次部署通道安装完成后启用。

协作者接受仓库邀请后，可以直接推送到 `main` 触发部署；日常修改也可以通过分支和 Pull Request 协作，合并到 `main` 后自动上线。这里的部署目标就是同一个在线站点，部署成功后访客可以看到新版本。

在仓库 **Actions → Test and deploy to Aliyun** 查看结果。GitHub 和服务器各执行一次测试；测试失败不会切换现有服务，切换后健康检查失败会回退上一代码版本。代码版本记录在 `/__deployment.json`。应用继续使用服务器已有的 `/opt/wall/data`，不会用仓库覆盖数据库、管理账户或上传图片；代码回退不回退数据库。

部署账户仅允许接收发布包，并有重启 `wall.service` 的权限，不提供 SSH 交互式终端。Actions 的 SSH 私钥保存在仓库加密 Secrets 中，不写进源码。安装接收程序 `deploy/receive.py` 的服务器维护者需要单独更新它，它不会随普通代码部署自动替换。

下方 Docker 部署章节供想独立搭站的人使用，现有阿里云站点继续使用原来的 systemd 服务和 Nginx。

## 在自己的服务器部署

准备一台 Linux 服务器、一个指向该服务器的域名，以及 Docker Engine 和 Compose 插件。放行 TCP 80/443（可选 UDP 443），这两个端口应未被其他 Web 服务占用。

```sh
git clone https://github.com/wanghan0826/suishouji.git suishouji
cd suishouji
cp .env.example .env
```

编辑 `.env`，将 `SITE_DOMAIN=wall.example.com` 换成自己的域名，不带 `https://` 或结尾斜杠。

```sh
docker compose up -d --build
docker compose exec app node admin-setup.mjs
```

第二条命令会交互式设置管理用户名和密码（6至256位，输入不回显，建议使用较长的独立密码）。没有默认密码，不能通过网页抢注管理员。需要重置时再次执行同一命令；重置会使所有旧管理会话失效，不影响普通用户账号和帖子。完成后访问：

- 网站：`https://你的域名/`
- 管理端：`https://你的域名/admin`

Caddy 负责 HTTPS 证书和反向代理。首次签发证书需要域名解析正确、80/443 端口可达；证书签发受证书服务商政策约束。Compose 内的应用没有向宿主机公开 8080 端口。

只允许在没有帖子的空站执行，避免反复插入。也可以直接通过首页发布自己的内容。配图来源见 [THIRD_PARTY.md](THIRD_PARTY.md)。

## 本地运行

安装 Node.js 24 或以上（需要内置 `node:sqlite`）。不需要执行 `npm install`。

```sh
node server.mjs
```

打开 `http://localhost:8080`。要使用本地管理端，在另一个终端执行 `node admin-setup.mjs`。本地 HTTP 模式仅监听 `127.0.0.1`，不能拿此模式直接公开到网络。

运行自动化测试：


## 已有 Nginx 等反向代理时

无需使用 Compose 中的 Caddy。可以安装 Node.js 24+，由自己的进程管理服务运行 `server.mjs`，设置：

```sh
SITE_ORIGIN=https://wall.example.com HOST=127.0.0.1 PORT=8080 TRUST_PROXY=1 TZ=Asia/Shanghai node server.mjs
```

Nginx 在 HTTPS 站点中反向代理到 `http://127.0.0.1:8080`，设置 `client_max_body_size 65m`、`proxy_set_header Host $host`、`proxy_set_header X-Forwarded-Proto $scheme` 和 `proxy_set_header X-Forwarded-For $remote_addr`。HTTP 入口跳转 HTTPS。管理端通过来源校验保护写操作，`SITE_ORIGIN` 必须与浏览器访问地址一致。

`TRUST_PROXY=1` 只应在应用仅能被可信代理访问时设置。标准 Compose 配置已用内部网络隔离应用。不要把应用 8080 端口直接映射到公网。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `SITE_ORIGIN` | `http://localhost:8080` | 完整站点来源，不带路径或结尾斜杠；公网必须为 HTTPS |
| `PORT` | `8080` | 应用监听端口 |
| `HOST` | `127.0.0.1` | HTTPS 部署的绑定地址；Docker 内设为 `0.0.0.0` |
| `DATA_DIR` | 项目目录的 `data/` | SQLite、管理账户和用户上传的保存位置 |
| `TRUST_PROXY` | 关闭 | `1` 表示信任代理传来的协议和客户端地址 |
| `TZ` | 由运行环境决定 | 建议 `Asia/Shanghai`，Compose 中已设置 |

## 更新、备份与恢复

更新前先备份，再更新代码并重建：

```sh
git pull --ff-only
docker compose up -d --build
```

站点数据保存在 `wall_data` 命名卷，证书保存在 `caddy_data`。普通重建不会清空数据；**不要执行 `docker compose down -v`，它会删除数据卷**。

为了让数据库和上传文件保持一致，可短暂停止写入后备份：

```sh
docker compose stop app
docker compose run --rm --no-deps --user root --entrypoint tar app -C /app/data -czf - . > wall-data-backup.tar.gz
docker compose start app
```

备份包含用户内容和管理账户派生值，应私下保管。恢复时在目标站停机状态下，将可信备份解压到数据卷，保证文件归容器的 `node` 用户（UID/GID 1000:1000）所有，再启动。不要把正在使用的数据直接覆盖为旧备份。

排查启动：`docker compose ps`、`docker compose logs --tail=100 app caddy`。证书失败先查 DNS 和 80/443 端口；登录来源错误先查 `.env` 域名和反向代理的协议头。

## 同频猜词 · 双人小游戏

打开 `/play`，或从“朋友动态”、个人空间进入“同频猜词”。登录后创建房间，将邀请链接分享给一位朋友；对方登录并确认加入后开始。首位确认加入的人占用第二个名额，不要求互相关注。

两人各写一个1–12字的词，提交后本轮不可修改。双方都提交后才揭晓：相同即同频成功，不同则根据上一轮继续联想。比较时忽略空格、大小写和全半角差异，同义词仍按不同词处理。支持刷新继续、查看已揭晓记录、主动结束，以及手动复制邀请或同频结果；不会自动向站外发送消息。

游戏使用现有账号和 SQLite，在现有数据库新增 `word_rooms`、`word_rounds` 两张表，随站点数据一起备份。游戏记录仅两位玩家可读；加入前只能看到邀请者用户名，不能读取答案。服务器按真实登录账号验证房间权限及提交身份，并校验写入来源和 CSRF。未揭晓时，接口只返回自己的词及对方是否提交，不返回对方答案。游戏不调用 AI，也不发布为公开帖子或评论。

房间有效期为7天，新加入或成功提交会续期；过期后不能继续访问，可重新开局。过期超过30天的数据会在后续创建房间时清理。页面最多展示最近50轮已揭晓记录，房间总轮次不受此限制。自己的最近10个未过期房间会显示在玩法首页。每个账号每小时最多新建6个房间，其他游戏操作每分钟最多60次。

`scripts/word-game.mjs` 负责游戏规则与接口，`public/word-game.*` 为独立页面、样式和交互。公开部署仍运行全套测试，新增用例覆盖双方揭晓、幂等重试、抢占房间、旁观者拒绝、过期、账号停用与未揭晓词保密。

## 小记 · DeepSeek Flash 助手

管理端数据概览的“小记”面板填写服务接口地址和 API 密钥，点击“验证 Flash 并启用”。模型固定为 `deepseek-flash`（[官方文档](https://api-docs.deepseek.com/quick_start/agent_integrations/)），不回退到 Pro。认证通过才保存配置，密钥只写入服务器 `DATA_DIR/ai-config.json`，不通过公开接口返回；无需写入源码或 GitHub。可随时在管理端停用。

启用后，新公开帖子和广场讨论各产生一条AI评论；评论中 `@小记` 或直接回复小记会生成定向回复。明确显示“小记 / AI助手”，不会冒充真人，不补刷历史帖子，不读取私人空间动态。目前依据帖子文字及最多8条可见评论回应，不解析图片和视频。相关公开文字会发至配置的模型服务。

任务在独立队列持久化，去重且串行处理；失败最多尝试3次，认证/余额错误不反复重试，不影响用户发帖。生成前后重新检查帖子、评论及账号的可见状态；AI评论沿用现有下架及回复线程规则。AI不主动回复自己的消息，也不记入真人社交参与行为。页面打开时每8秒检查新评论，不自动滚动或覆盖编辑中的文字。

## 手机竖屏弹幕与网页测试台

手机宽度不超过760 CSS px时默认使用双行短标题弹幕。发布短帖或社区帖子时可填写独立“弹幕文案”，最多24个字素（完整表情算一个），不覆盖正文。未填写则使用正文首行／讨论标题的最多24字摘要，长文明确标为“摘要”；不再用单行隐藏正文。短标题表情不截断，轨道按实际卡片高度重新留距，较宽卡片适当减速。触屏按住约300毫秒只暂停该条，松开恢复，长按后不立即跳转；同轨后续卡片会留出间距。打开、关闭帖子和尺寸调整仍沿用原循环进度。`?wall=classic` 可对比旧版，电脑端保持原展示方式。

测试台验证布局，不会改变设备UA、真实DPR、系统字体、触屏、软键盘或GPU性能。可用高度、系统显示大小与浏览器栏位仍应在本人手机校准，不能把预览结果当成完整真机测试。

`/wall-demo` 使用明确标注的8条客户端演示内容，可打开对应演示正文。所有模拟API在当前页面返回，账号、发布、点赞和评论等写入被拦截，访问统计也不发送；演示记录不会进入正式数据库。离开演示去游戏／社区需通过测试台切换，真实页明确提示操作实际生效。不要将演示帖子编号当作正式帖子链接传播。

## 统一手机操作层

手机端底部导航统一为弹幕、游戏、发布、社区、我的。首页保留直接发布弹幕，社区页面打开当前编辑器，其余页面的发布入口进入 `/plaza?write=1`；只恢复编辑界面，仍需本人填写与确认。阅读帖子时仍使用原来的收起／评论／分享操作栏，电脑不显示手机导航。

手机端的公开发帖、社区发帖与个人资料表单采用固定标题与底部提交栏，中间字段独立滚动，滚到底仍能关闭或保存。共享 `touch-ui.js` 根据浏览器 `visualViewport` 更新可用高度，键盘占据明显空间时收起底部导航、限制弹窗到可见区域，并滚动当前输入框；旧页面原有草稿与登录接续逻辑保留。按钮触达尺寸最低44 CSS像素。相关布局通过正常手机宽度和模拟缩短可见视口验证，真实系统键盘与设备交互仍需真机确认。

首页与社区的附件选择器共用 `attachment-picker.js`：显示已选文件名、类型、大小和图片预览，可单独移除附件；更换、移除、重置或成功发布时释放旧预览资源。空文件、超过60MB和不支持的格式会立即提示并清空选择，避免看见旧图片却实际未附带文件。不会自动播放所选视频。关闭编辑窗口保留草稿和附件，主动退出账号清理。提交期间锁定字段，避免网络等待时改动内容而被旧响应清空；网络失败恢复编辑并提示草稿保留。社区的旧悬浮发帖按钮在使用统一底栏时隐藏，避免被底栏遮挡。

竖屏测试台新增个人资料/空间、朋友动态及420×520短视口压力预设。该预设预留模拟栏位后iframe视口为420×424，用于检查狭小可用区域的表单；不模拟真实系统键盘。

主题设置中的“首页省流模式”保存在当前浏览器，浏览器提供 `navigator.connection.saveData` 时默认遵从系统省流偏好，手动选择优先。开启后首页弹幕使用主题图标，背景固定为本站湖景，不轮播帖子原图；下方图文在接近可见区域时才加载，视频预览不预取元数据。点击帖子仍显示完整内容。关闭省流可恢复配图和原有轮播选择，切换不重置弹幕队列。已经下载的资源不会退回流量，其他页面及帖子详情不受此首页选项限制。

首页和社区发帖会为当前未改动的草稿携带随机发布凭据。遇到“服务端已发布、成功响应丢失”的弱网情况，再次点击发布返回同一篇帖子，不重复创建帖子、附件或参与记录。修改正文、分区、主题、弹幕文案、附件或切换账号会开始一次新发布；关闭再打开同一编辑窗口保留凭据，刷新页面会重建。不会在后台自动提交或自动重试。

新增 SQLite `post_requests` 表，与帖子及分区、弹幕文案在同一事务写入；相同凭据仅属于登录账号本人，内容不一致返回409，原帖下架或删除返回410。并发重试产生的未使用附件会移除，原有不携带凭据的客户端仍兼容。登录、账号封禁、来源和CSRF验证始终先执行；每分钟6次新发布的限制保留，已确认重试不占新发布次数，上传请求另限每分钟30次。

手机主题、分享及空间/朋友详情弹窗的标题和关闭入口在内部滚动时保留在顶部。评论、空间动态、空间弹幕和朋友留言提交成功时，仅清空实际提交且未继续修改的文字；网络等待期间继续输入的草稿保留，切换帖子、详情或账号后旧响应不覆盖当前编辑状态。相同表单等待期间拒绝重复提交，网络异常保留文字并显示中文提示。这些评论和空间留言不使用公开帖子发布凭据，不进行后台重试。

同频猜词在输入框旁显示字数、校验与提交失败提示，校验规则与服务端一致：去掉首尾空白后1–12个Unicode字符，不接受换行或隐藏控制字符；不在中文选字过程中提交。锁定期间显示“锁定中”，下一轮及已确认提交时才清空本轮输入。只读同步一次最多等待一个请求，8秒未返回即取消并在后续轮询重连；切到后台、离开页面或切换账号会取消旧的只读请求。断线和重新连接不改写未提交的词，不自动提交或重发答案；服务端原有同轮同答案幂等规则及两人隐私不变。相关检查使用本地两账号、浏览器手机尺寸画布及受控网络延迟，不代表真机键盘或实机网络测试。

从首页图文或弹幕展开帖子后，“收起”和浏览器返回会回到原来的浏览位置，切换正在阅读的帖子不增加一串阅读窗口记录；直接打开帖子链接时，收起回到首页。弹幕仍沿用原有队列与播放状态。`/wall-demo` 的阅读地址保留演示路径和新旧弹幕选项，刷新仍读取演示内容，不生成正式帖子链接。

社区的分区、游戏标签、主题、排序、搜索词和页码与URL同步，返回或刷新后从该条件重新读取公开结果；手动翻页从新一页的第一条开始。社区在当前浏览器历史记录中记住可见公开帖子编号及位置，仅恢复24小时内且仍在结果中的位置。记录不包含账号凭据、私人空间内容或编辑草稿；加载失败不覆盖旧位置。配图预览预留16:10空间，完整图片仍在帖子中查看，减少慢加载引起的位置跳动。

首页弹幕滚出屏幕、网页离开前台或手机展开全屏阅读时，保留当前队列和位置并停止逐帧更新；回到可见区域后接着播放，用户手动暂停仍优先。保留弹幕可见区域的手机半屏阅读、电脑旁栏和展开阅读继续播放。背景图片轮播也在不可见时停表，恢复时沿用原开关和当前图片，不追赶离开期间的变化。逐帧批量读取区域宽度，仅更新实际移动的条目；本地浏览器检查覆盖暂停、滚动、全屏、缓存返回和系统减少动态效果偏好，没有据此推算手机耗电百分比。

帖子配图默认在站内全屏查看，支持按钮、滚轮、双击及双指缩放，放大后可拖动，最多相对适应尺寸放大6倍；“适应”恢复完整图片。顶部关闭按钮、Escape和浏览器返回只关闭图片层，恢复帖子内的阅读位置；前进、刷新及 `#image` 链接可重新查看图片，须先正常读取对应的公开帖子。“查看原图”保留原有新标签入口，脚本不可用时原链接也仍有效。图片加载失败显示手动重试，关闭时释放查看器的图片来源和交互状态。

图片层覆盖屏幕时暂时停止背后的弹幕，关闭后按原暂停状态恢复；不改变帖子、评论或上传文件，也不把私人空间头像接入公开查看器。检查覆盖手机/横屏/电脑布局、浏览历史、缓存返回、加载失败和受控双指事件；未将浏览器事件模拟称作手机真机触控测试。

GitHub发布时按每个公开脚本、样式的文件内容生成缓存版本号。内容未变的文件沿用原地址，修改文件后只更新对应地址；仅更新说明或其他资源时，已有有效缓存可以继续使用。现有查询参数和片段保留，缺失文件或越出公开目录的引用会阻止构建。管理端及登录、API、私人头像的缓存与访问控制沿用原规则。

构建生成的 `/__asset-manifest.json` 仅记录发布提交号及公开脚本/样式的版本，部署后会校验提交号与清单。首次从旧版本号策略切换时需要重新获取脚本和样式，后续更新可按内容复用缓存。本地浏览器对照检查包含冷访问、再次访问、仅更换发布号和单个脚本实际更新；传输量来自该检查，不代表所有手机网络的固定节省值。

### 新用户来源与游戏参与

管理端新增“用户增长”，可选择近7天或近30天。按注册日统计新增账号、实际参与游戏的账号、游戏页面注册、首次从游戏房间进入的注册，以及注册首日游戏参与、玩后社区发言和当前互关情况；按首次到访日另外统计入口/渠道到访批次与后续注册，避免把两种分母混为一谈。仅站主管理会话可读，接口为 `/api/admin/growth?days=7`，不返回用户名、房间码、猜词正文、私人内容、IP或密码信息。

匿名浏览器首次打开正常公开页面时记录入口类别及有限的渠道类别，首次来源7天内保持不变。随机标识放在 HttpOnly、SameSite=Lax 的 Cookie，正式环境使用 Secure/Host-only；数据库只存其散列。一次浏览器来源最多关联一个新账号，不凭已有账号登录反向归因。QQ/微信等不提供来源时显示“直接或未识别”；链接标记和浏览器来源均是未核验线索。仅保存类别，不保存完整URL、查询参数、外站地址、空间用户名或房间凭据。识别到的爬虫、预加载、HEAD、测试台嵌入页和已登录页面访问不增加首次到访。用户注册说明已包含该汇总用途，没有问卷或额外注册步骤。

同频猜词以服务端成功提交词为参与；你画我猜以服务端成功接收实际画笔或合法猜测为参与，后者每人每轮至多记一次。创建/加入房间、浏览、同步读取和相同画笔重试不计新参与。参与摘要及逐日计数与对应游戏操作同一事务提交。首日玩家次日/第7日回访以注册日为第0日，目标北京时间日历日完整结束才进入分母；再次实际参与上述游戏才算回访，未成熟批次显示待观察。“玩后社区发言”从本次记录到的首次游戏操作后成功发帖、评论、空间动态或留弹计算；当前互关按现存关系计算，均排除封禁账号。

历史用户只能依据仍保留的房间/词记录补算“确认玩过”，不向前补造来源、首次游戏时间、当天参与或精确回访；旧房间被清理可能使历史人数低估。新记录的首次游戏摘要不随旧房间清理消失。访客到访与逐日游戏数据保留约90天，在后续正常页面访问时清理，注册来源和首次参与摘要随账号记录保留。入口和参与的关联不能证明注册动机或推广的因果效果。


### 灵魂画手：单人开画与多人抢答

入口 `/draw`，也可从游戏大厅进入。账号登录后创建私人画室，通过 `/draw/<随机房间凭据>` 邀请朋友，最多10个同时在场账号。默认自由画室：1人可开始，由房主一直负责画，朋友可在开画后或结算间隙加入，加入后可猜当前题。每题90秒，结算8秒后由同一画者画新题；房主结束或离开会关闭画室。连续10分钟无人绘画、答题或其他有效操作会自动结束，避免无人画室无限换题。轮流挑战保留原规则：3–10人开局，名单固定，按座位每人画一题。题目从本站词库选择，不调用AI或付费接口。轮转、截止时间、答题顺序与结算均以服务器为准，刷新可恢复当前画板和积分；进程恢复后根据数据库时间继续结算，不依赖玩家前台计时器。

自由画室采用猜中得分的基础玩法，参考 [skribbl 官方玩法](https://skribbl.io/) 中画者作画、其他人猜词的流程，以下具体分值由本站自行定义：猜中者按服务器顺序得100、80、60、40分，之后每位20分；画者每带来1人猜中得10分。全部猜中仍正常得分，无人猜中不计分，单人练画不计分。新观众加入不会改变已猜中者的暂定分。普通观众离开不取消整轮，回到同一轮不重复计分。

轮流挑战若本轮有N名猜题者，第1位正确者暂定N分，第2位N−1分，依次递减；画者暂定获得猜中人数的分数。回合结束统一加到总分，若所有猜题者都猜中，本轮画者与全部猜题者一律0分，没有人猜中也无人得分。结算只执行一次，相同账号重复猜中不增加名次或分数。超时后到达的答案不再计分。为避免改变分母，中途主动离开会取消当前轮计分，开局后离开的账号不能重新加入该局；房主离开会顺移房主，不足3人结束整局。普通断线或切后台不视为主动离开。房主可以跳过本轮并全员0分，跳过和提前继续都绑定轮次，延迟请求不能误操作新一轮。

画笔以规范化坐标分段实时同步，服务端保存矢量笔迹；事件流使用SSE，关闭代理缓冲并定期心跳。每个事件流及后续写入均重新检查登录和成员权限；答案仅发给当前画者，结算前不会发给猜题者，正确答案不作为聊天正文广播。非成员只看到房主、人数、状态和是否可加入。绘画权限只属于当前画者，猜题者不能改画板；操作检查轮次、画板版本、颜色、粗细、坐标和体积，并有按账号限流。并发加入不会突破10人。笔迹操作有唯一标识，响应丢失后重试不会重复保存；清空、整笔撤销会提升画板版本并拒绝旧笔迹。每轮限制1200段/30000点，可清空后继续；慢接收端积压过多时关闭流，重新连接恢复快照。

手机支持手指绘画、颜色、橡皮、粗细、整笔撤销和清空。开画和结算时采用视口内沉浸布局：隐藏网站顶部和全站导航，主区域是画布，底部固定观众积分与回答，可横向查看全部成员，回答按钮始终可点。按创建者设备选择480–1600高、960宽的房间画布，同房间所有设备等比显示；鼠标/触控坐标扣除留白，避免跨设备笔迹拉伸或偏移。抢答输入框跟随可视视口变化；猜测以轻量弹幕出现在画板上沿，开启系统减少动态效果时不播放此动画。后台、断线、回前台会重新同步；未上传的画笔仅在当前页面重试，关闭或刷新页面不承诺恢复尚未同步的笔迹。退出账号或离开会清除页面中的私有游戏信息。回合结算后可由玩家手动保存画作，整局结束可手动复制本人战绩；不会自动发布到公开社区。

SQLite表 `draw_rooms`、`draw_members`、`draw_rounds`、`draw_correct`、`draw_strokes`、`draw_messages`、`draw_activity` 保存实际房间、轮次、抢答顺序、画笔与参与记录。房间有效期7天，过期超过30天的房间数据在后续创建画室时清理；成员凭登录会话及画室凭据访问，不把词和房间内容加入公开帖子、AI助手或增长报表。增长看板新增你画我猜的入口类别，游戏参与/回访覆盖两款游戏，具体游戏操作仍按各自规则确认。手机测试台新增你画我猜页面，真实操作仍会实际生效。

验证覆盖真实登录与来源/CSRF校验、十人并发容量、题目保密、画板版本/撤销/恢复、分数顺序、全中清零、到时结算、轮转、离开转房主、过期/封禁及实时事件流。浏览器隔离环境使用三个真实测试账号验证同步绘画、受控触屏输入、离线重试、刷新、手机底部抢答和退出清理，覆盖320/420/837/1280像素及420×450短视口；这些是浏览器测试，不是真机或十台实体设备同时在线压测。

### 玩家游戏建议与大厅入口

游戏大厅 `/games` 首先显示两款游戏的入口卡片：双人同频猜词、1人可开画的灵魂画手。点击后分别进入 `/play`、`/draw` 查看各自玩法，再选择开房或加入；大厅不再堆放两款游戏的长介绍，点击入口也不自动创建房间。卡片适配手机竖排、桌面并排，并保留原有Q版插图。游戏建议与社区入口放在游戏入口之后。

`/feedback` 提供“下一款游戏，你想玩什么”表单，游戏大厅及两款游戏页面均有入口。用户登录后填写游戏名称/想法（1–50个Unicode码点）、偏好的单人/双人/多人模式，以及选填的玩法说明（最多800个码点）。建议不作为公开帖子，也不会触发AI自动回复、私信或站外消息。登录只接续填写，不自动提交；匿名填写后登录保留当前页面草稿，明确退出或切换已有账号会清除草稿和私有列表。

SQLite `game_feedback` 持久保存建议与处理进度。`/api/game-feedback` 仅供当前登录账号提交或分页查看自己的建议，绑定服务端会话，不采信传入的作者或状态。新提交需通过TLS、来源和CSRF校验；每账号按北京时间每天最多5条。同一未改动建议使用随机提交标识，提交成功但回复丢失时重试返回原建议，不占额外名额；修改内容会使用新标识。提交凭据不出现在用户列表或后台返回中。未同步的草稿只保留在当前页面，刷新后不承诺恢复。

验证覆盖账号隔离、来源与CSRF、限额、弱网提交去重、处理状态、回复、并发编辑冲突、分页及文本安全。浏览器隔离测试验证匿名草稿登录接续、明确提交、成功响应丢失后重试、站主处理到作者查看的完整流程、退出后迟到响应、320/420/1280像素和420×450短视口；并检查手机首屏可见两款游戏卡片、分别跳转到玩法页面且不自动开房。手机测试台新增游戏建议页面，仍是操作实际生效的真实页面。

### 区分操作入口和普通说明

公开页面统一加载 `interaction.css`：游戏卡片的“查看玩法/进入”显示实色动作条，反馈、社区分区和其他整卡入口显示描边动作条，普通文字链接保留下划线。完整卡片仍是一个原生链接，不把按钮嵌套到链接内；点击、键盘Enter及原有跳转行为一致。首页游戏入口、游戏大厅、游戏页面、社区、反馈和朋友页面采用相同规则。原有“想玩新游戏”重复文字入口从大厅标题区移除，主游戏卡片优先展示，建议卡片继续在下方提供入口。

人数、玩法、示例词和处理进度使用无按钮边框的说明样式，反馈状态以小圆点配文字展示；非交互元素不增加点击行为。动作在默认状态已有明确外观，另外提供鼠标悬停、按下、键盘焦点及禁用态反馈；减少动态效果偏好下不执行新的抬升动画。首页弹幕及私人空间的行为和权限沿用原规则。

浏览器检查覆盖320/420/1280像素的公开页面、八种主题、主要操作的文字对比度、键盘跳转、登录入口和减少动态效果设置，并继续验证手机首屏两款游戏入口都位于底部导航上方。
