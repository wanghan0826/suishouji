# 手机牌桌布局与验证

麻将牌桌、斗地主使用同一横向画布尺寸约定（`game-landscape.css`）。手机竖持时将牌桌画布顺时针旋转；自然横屏时恢复普通布局。麻将大厅采用自然竖屏与页面滚动，仅入座后启用横向画布，返回大厅时退出。按钮“全屏”仅增强浏览器全屏显示，横向牌桌不依赖其成功与否。

## 斗地主

- 自己的牌在底部单行重叠排列，角标保持可见。牌少时按实际张数收拢，选中抬起，不改变其他牌的位置。
- 点击可切换单牌；滑动可选中或取消连续一段牌。取消范围以手势开始时的选择状态为准，来回滑动不会重复翻转。
- 触摸沿用起始牌的隐式指针捕获，鼠标拖动使用显式捕获；通过屏幕坐标命中测试兼容 CSS 旋转。
- 三家出牌在各自座位附近显示，最近一手高亮。“不出”和叫分信息也跟随玩家。
- 使用服务器提供的公开动作，不读取其他玩家私有手牌。玩法、计分与房间协议保持原有约定。

## 麻将

- 放大自己的手牌，摸入牌留出间隔，已碰杠牌与手牌同排但独立分组。
- 四方牌河围绕桌心排列，按剩余空间调整牌面尺寸。极短屏或大量弃牌时，点击牌河打开大牌面查看，不会丢弃牌河记录。
- 放大查看只包含已经公开的弃牌；响应窗口、计分、隐藏暗杠与服务端规则沿用既有实现。
- 自摸、碰、杠、过及确认打牌位于手牌上方。聊天面板位于桌面左侧，自己的手牌保留在下方，右侧确认打牌按钮保持可点。
- 报牌音频和快捷表情沿用现有实现。

## Mahjong voice and response improvements

- 普通话女声报牌覆盖34种牌名，音频制作说明见`design/mahjong-female-voice.md`。进入牌桌即预载解码，用户触摸后允许播放；同一出牌事件只播一次，1.8秒以前的积压声音不补播。报牌开关继续保存。
- 已入座玩家通过`GET /api/mahjong/:token/events`接收SSE私有视图。出牌、碰杠、准备和聊天提交后立即推送；机器人和超时处理由原有500ms维护任务触发。心跳15秒，登录、入座、关闭和过期均重新检查。每个账号最多3条连接，慢连接积压受限。不会向其他玩家推送手牌、牌墙或暗杠牌面。
- 前台连接健康时停止1.2秒轮询；不支持SSE或连接失败时恢复轮询，按退避间隔重连。进入后台、离线、离开房间或退出账号立即关闭连接；35秒没有状态或心跳时重新连接。
- 手牌按牌种与重复序号保留节点，其他玩家的更新不再清掉选牌；头像、牌背和牌河按变化更新。34种SVG牌面使用模板复用；牌河尺寸在同一帧集中读取、再写入，避免交替读写布局。新增摸牌与落牌140ms短动画，尊重减少动态效果的系统设置。
- 点「打出」立刻显示「正在出牌」及选中牌反馈，提交期间阻止重复操作；服务器确认后更新手牌，失败后恢复操作。结果和积分仍以服务器状态为准。
- 本地两账号、420×933触摸模拟验证节点保留、选牌保持、无空闲轮询、故意延迟180ms的请求、断线重连、失败恢复、静音、无重复报牌与退出回大厅；延迟请求下对手落牌显示约230ms，属于本地模拟结果，不代表真实手机或公网延迟。原四账号完整对局、320–420竖屏与568–933横屏、过期自动回大厅的回归均验证。全部测试数据位于独立本地SQLite。

## Automatic settlement and shared Mahjong rules

- 胡牌与流局后自动显示独立结算画面，四家剩余手牌、碰杠牌、本局积分与总分默认展示。胡牌者金色高亮；自摸从原手牌中取出一张胡牌张单独标记，点胡与一炮多响则各展示对应获胜者的胡牌张，避免自摸牌重复。
- 四家牌面按可用宽高统一缩放，手机竖屏仍使用既有横向画布。计分明细单独打开，保留番型、封顶、抢杠胡、杠分与付款规则；只有房主可开始下一局，所有人都可返回大厅。下一局和退出账号会清除旧的公开结算，活动对局仍隐藏他人手牌与暗杠内容。
- 本地四个独立账号检查自摸、含明暗杠的胡牌、一炮多响、整桌最后一局和流局。每种检查568–1280px横屏及320–420px竖屏模拟，共50组结算布局；检查全部牌面、四行卡片、积分与底部按钮可见、重进恢复和下一局隐私恢复。未在实体手机或生产数据库构造测试局。
- 大厅新增公开规则方案：在开房区设好规则后点击“把当前规则发布到大厅”，可填写最多20个Unicode字符的单行说明（可留空）。保存到新增的`mahjong_rule_presets`表，关联发布账号；发布方案本身不会创建房间。
- `GET /api/mahjong/presets`公开分页浏览，每页12条；`GET /api/mahjong/presets/:id`查看完整配置。登录、通过现有CSRF检查后才能`POST /api/mahjong/presets`发布。请求凭据保证网络丢失响应后重试不会重复发布；每人最多10条公开方案，每小时最多发布6次。作者可通过`POST /api/mahjong/presets/:id/remove`下架自己的方案，已开牌室不受影响；禁用账号的方案不再公开。
- 其他用户可以查看完整配置并“套用开房”，创建属于自己的独立牌室，沿用全部已支持的家规字段。没有把规则方案当作公开房间入口，也没有公开原房间号、座位或手牌。
- 本地浏览器验证20字中文/Emoji计数、21字阻止提交、丢失响应后重试、游客浏览与登录提示、跨账号套用、作者下架及320–420px大厅和弹窗；服务端测试验证严格规则校验、分页、持久化、登录与CSRF、所有权及发布限额。

## Custom multipliers and independent rob-kong

- 七对、豪华七对、门清、碰碰胡、混一色、清一色、全字牌、单吊、开杠、杠上开花，均有独立启用开关和1–64整数倍率。默认沿用原来的4、8、2、2、2、4、8、4、2、2倍；1倍保留该牌型但不额外翻倍。关闭后暂停计入，表单会保留有效的自定义数值。
- API增加十个同名`Factor`后缀字段，例如`sevenPairsFactor`和`singleWaitFactor`；拒绝0、负数、小数、字符串和超过64的数值。计分按各项实际倍率相乘、受本桌上限约束、再乘底分。明细显示原始倍数和封顶后的倍数。最大可组合倍率也校验整数精度与积分守恒。
- 原“金钩钓”在规则设置、牌型判定输出及旧结算展示中统一称为“单吊”；沿用原判定：四组碰杠后，剩一张手牌配对胡牌。没有将普通门清手牌的将牌等待扩展为此加分项。
- “允许抢补杠胡”与“只自摸”独立：只自摸限制普通弃牌点胡，开启抢补杠胡后仍可响应别人的补杠。暗杠不进入抢杠窗口；抢胡成功时保留原碰牌、不收补杠分、不补摸，结算标记抢杠胡与被抢杠者支付；全员放弃时才完成补杠。关闭开关时直接按原补杠流程处理。
- 旧房间和旧规则方案缺少新字段时使用原倍率；读取补齐默认值，不重写旧房间。旧方案的丢失响应重试仍按规范化规则比较，避免升级后重复发布。新方案发布、查看和套用开房均完整携带自定义倍率及独立抢杠选项。
- 本地检查全部十项倍率、边界值、非2的幂、1倍、关闭牌型、封顶、默认兼容和旧记录重试；四账号浏览器验证实际计分、单吊与旧名称兼容、自摸模式下抢补杠胡和禁止普通点胡、抢杠关闭与补杠成功。320–420px手机模拟检查倍率输入布局、非法值阻止发布、勾选切换和方案跨账号套用。
